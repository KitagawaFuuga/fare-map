# 0002: デプロイの前にも E2E を走らせる

- 日付: 2026-11-15
- 状態: 採用

## 背景

デプロイ前の検査は lint・型検査・単体テストだけだった。地図が白いままになる
不具合（maplibre のワーカーが 404）のように、ビルドも型検査も通って E2E で
しか出ないものがある。E2E は CI 側にしかなく、デプロイを止める位置になかった。

## 選択肢

- 案A: 足さない。0001 で PR の時点の E2E が必須になったので、それに任せる。
  `workflow_dispatch` での手動デプロイは E2E を通らない
- 案B: deploy.yml に E2E のジョブを足し、deploy がそれを待つ。CI と定義が
  重複し、main への push で E2E が2回走る
- 案C: ci.yml を呼び出せる形（`workflow_call`）にして deploy から使う。
  重複はなくなるが、2つのワークフローの構成を変える

## 決定

案B。デプロイを止める検査は、デプロイと同じワークフローの中にあるほうが、
ブランチ保護の設定が外れたり手動で実行されたりしても効く。重複は既存の
`test` ジョブと同じ形で、今は構成を変えるほどの量ではない。

## 結果

- デプロイが E2E のぶん（2分程度）遅くなる
- ci.yml と deploy.yml の E2E の手順を、変えるときは両方直す必要がある
