# 0004: テストの検出力をミューテーションテストで測る

- 日付: 2026-11-23
- 状態: 採用
- 決めた人: ユーザー（AI が出した案から選んだ。進め方と、測る範囲の2回）

## 背景

開発を AI に任せる範囲を広げると、誤りを止めるのはテストだけになる。テストの
件数（1047件）やカバレッジでは、テストが実際に誤りを捕まえられるかは分からない。

## 選択肢

進め方:

- 案A: 週1回、全体を測るだけ。マージは止めない
- 案B: PR ごとに変わったファイルだけ測り、基準を下回ればマージできない
- 案C: A から始め、数週分の実測を見て基準を決めてから B を入れる

測る範囲（全体の計測で、実データを読むテストが Stryker の計測下で1件数分かかり、
最初の全テスト実行すら終わらないことが分かった後に決めた）:

- 案A: 実データ（data/ の路線網・運賃表）を読む11ファイルを外して測る
- 案B: 全部含める。時間が読めず、GitHub の1回の上限（6時間）を超えるおそれ
- 案C: 壊す対象を、実データに頼らないファイルに絞る。運賃計算と探索が測れない

## 決定

進め方は C、測る範囲は A。基準の値は実測を見てから決める（1事業者で決めた
閾値が他で破綻した経験がある）。知りたいのは「AI がコードを壊したとき、速い
テストで捕まえられるか」で、PR で止める段階でも使えるのは速いテストだけ。

道具は Stryker（StrykerJS 10.1.1、vitest runner）。Stryker から流すときだけ
`vitest.stryker.config.ts` を使い、実データのテストを外して1件の制限を延ばす。

## 結果

- 2026-11-24 の手元の計測（8コア）: 3052通り、約24分、スコア 68.0%
  （捕まえた 2074 / 見逃し 802 / 通るテストが無い 176）。Stryker が数えたテストは 788件
- 2026-11-25 の GitHub での初回（main、手動実行）: 約6分半（Stryker 本体は5分16秒）、
  スコア 67.96%（2074 / 802 / 176、手元と同じ）。テストは同じく 788件。手元より4倍速いのは、
  Windows でテストの実行環境を立ち上げ直すのが遅いためと見ている（未確認）
- テストの数は数え方で違う。`vitest run` は 39ファイル・825件（飛ばす3件を含む）と出すが、
  Stryker は lib/ を通らない6ファイル（`mutation-summary.test.ts`・`slow-test-naming.test.ts` など）を
  一覧に出さない（28件）。飛ばす3件も数えない。残る6件の差は調べていない。測る範囲が
  変わったわけではない
- 外すテストは名前（`*.slow.test.ts`）で決める。全国の路線網（data/graph.json）を
  読むテストを入れると、壊したコード（終わらないループなど）が実際の路線網の上で
  回り、時間切れとメモリ不足で計測全体が止まった（3109通り中361通りで停止）。
  路線網を読むテストがこの名前になっているかは `slow-test-naming.test.ts` が検査する。
  この検査はファイルの文字列しか見ないので、計測中に路線網を読んだら落とす仕組みも
  入れた（`vitest.stryker.setup.ts`）。止めるのは readFileSync・fs/promises・JSON の import で、
  createRequire 経由とファイル記述子での読み込みは止めない
- `lib/server/graph-store.ts` は 0%。テストが無いのではなく、テストが本物の路線網を
  読むので計測から外している（.slow 側）。スコアの「通るテストが無い」176 にはこの分が入る
- スコアの読み方の注意: 型検査（checkers）を入れていないので、型の合わない壊し方も実行され、
  テストが落ちれば捕まえた側に入る（高めに出る）。逆に、テストの読み込み時に落ちた57件
  （RuntimeError）は実際には捕まえているが分母から外れる（約0.5ポイント低めに出る）
- 見逃しの多い壊し方は、条件を常に true/false にする（298）と `<` `<=` の入れ替え（114）。
  境界値のテストが薄い。ただし、結果が変わらない壊し方（並べ替えの比較の `<` → `<=`、
  `size >= 0` など）も多く含むので、114件すべてが穴ではない。例: `lib/fare/calculator.ts` 70行目の特定都区市内の距離判定で、
  `>` を `>=` に、`<=` を `<` にしても落ちない
- 初回（2026-11-23、59.4%・約14分）は `calculator.test.ts` と `verify-candidate.test.ts`
  をファイルごと外していて、中の速い単体テストまで数えていなかった。いまは
  路線網を使う部分だけを `*.slow.test.ts` に分けて、残りは測っている
- スコアは実データのテストが捕まえる誤りを数えないので、実際の検出力より低く出る
- 週1回の実行結果は、ジョブの要約欄と成果物（90日保存）に残る。次の段階
  （PR で止める）の基準は、これを数週分見て決める
